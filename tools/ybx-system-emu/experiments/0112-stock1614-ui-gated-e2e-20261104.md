# 0112 — Stock X4Pro: UI-gated automated Clippings E2E

2026-11-04. Real Stock CrossPoint 2.0 RC firmware within local QEMU 11.1.2; synthetic EPUB and fake KoSync. **Automated E2E is not green.** No real X4 Pro hardware or production API was used.

## Bugs reproduced and fixed in the test driver

1. The prior More detection used a dark-pixel threshold, which can match highlighted book text. New matching checks separate visual anchors from genuine E-Ink screenshots (with false-positive regression tests).
2. Library was incorrectly assumed to contain the first fixture EPUB. The actual test book is `/books/ybx/upload_fixture-1 - Fixture EPUB One.epub`; Library contains unrelated `README.md` and `HTML Hidden Tests`. The driver now uses Browse Files and checks each folder.
3. File-browser rows bring up a `Filename → Open` modal: unconditionally tapping the row can leave the runner stuck on the modal. The driver checks and activates the Open action explicitly.
4. After tapping `Clip`, the selected word remains dithered. Waiting for the highlight to disappear gives a false failure. A visible `View Clippings` menu entry is now required as proof of an on-device save.
5. The two-step navigation through the More menu is now guarded by the visible `Sync Progress` label, not blind taps.
6. After `Sync Progress`, the Wi-Fi picker must show `PICSimLabWifi`. Accepted QMP input alone is not accepted as a successful connection.

## Local checks and limitation

- Python UI-anchor/driver/fixture tests: 16 passed before the final negative Wi-Fi-stall unit was added.
- First end-to-end on clean SD reached the file-browser Filename→Open modal and exposed the missing dialog handling.
- The next run successfully reached **real firmware Wi-Fi picker**, after creating a clipping and verifying `View Clippings`. Four accepted injected taps did not leave that screen; no device-originated clipping GET/PUT traffic was emitted in this run.
- Therefore this automated run is **blocked at QEMU Wi-Fi/GT911 input processing**, not green; the previously documented manually driven Clippings v2 GET→PUT→GET and KoSync progress PUT remain separate evidence. ## Browser click -> accidental Uninstall (same-day live reproduction)

The actual browser preview on QEMU 8896 sent **170 ms** touches by default.
Clicking the Stock 1.6.14 `YBX` picker row with **150 ms** input reproduced
`Uninstall plugin / Uninstall YBX and delete all of its files?`,
which was **cancelled**; no uninstall was confirmed. The same picker row with
**60 ms** input opened the correct catalog path and then the native firmware
Wi-Fi selector. Therefore this is a touch-duration/long-press artefact of the
accelerated experimental QEMU, not evidence of an invalid 1.6.14 manifest.

The **browser default** and `/api/tap` fallback are now 60 ms. Explicit
longer durations remain possible for deliberate manual/QMP research taps.
The preview bridge was restarted without restarting the QEMU guest, and the
existing Chrome preview tab was reloaded. The independent Wi-Fi picker stall
remains a separate, unresolved E2E blocker.
