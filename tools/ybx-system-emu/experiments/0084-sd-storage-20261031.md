# 0084 — what the X4 Pro guest actually reads and writes on the FAT16 SD image

Date: 2026-10-31. Lane: batch-5, branch `agents/ybx-emu-b5-sd-storage-20261031`.
Private container: `ybx-b5-sd-storage-8795`, loopback port 8795 only. The
orchestrator's live container `ybx-x4pro-browser-8784` was never contacted.
All guest runs used a copy of the card inside the bridge temp directory; the
QA media were opened read-only and re-hashed at the end.

| Guest | FAT16 read | Directory listing | SD writes | Evidence |
|---|---|---|---|---|
| factory flash `206ed966…9523` | yes | Library: `notes.txt`, `HTML Hidden Tests`, `Title` (`1/3 books`) | library index, but **zero bytes on plain boot** | §5 |

  writes a cache (`book.bin`, `html/0.html`, `sections/0.bin`,
  `progress.bin`, `css_rules.cache`, `recent.json`, `state.json`).
- No host-side media file changed. The pristine image still hashes

## 3. Probe design and code map

`tools/ybx-system-emu/probe_x4pro_sd_content.py`:

| Function | Line | Role |
|---|---|---|
| `parse_mbr` | 64 | MBR partition table, 0x55AA, bounds |
| `parse_fat16` | 104 | BPB validation, FAT16 cluster range, layout |
| `read_fat` | 177 | reads and cross-checks both FAT copies |
| `format_short_name` | 203 | 8.3 name as stored (upper case) |
| `display_short_name` | 212 | honours NT case flags (0x08/0x10) |
| `parse_dir_entries` | 243 | 32-byte records, LFN, deleted/end markers |
| `cluster_chain` | 283 | chain walk with cycle and bounds detection |
| `read_file` | 314 | reads file bytes through the chain |
| `free_space` | 324 | free/used/bad cluster accounting |
| `walk_tree` | 337 | recursive tree, per-file SHA-256, caps |
| `inspect_image` | 402 | one read-only image summary |
| `diff_sectors` | 455 | merged changed-LBA ranges |
| `diff_fat` | 491 | allocated/freed/retargeted clusters |
| `diff_root_entries` | 533 | added/removed/changed root entries |
| `diff_trees` | 553 | recursive added/removed/changed paths |
| `diff_images` | 573 | full diff, free-space delta |
| `analyze` | 629 | report + contexts |
| `extract_changed` | 667 | copies guest-created files out, refuses overwrite |
| `main` | 697 | CLI: `--pristine`, `--guest-card`, `--report`, `--extract-dir`, `--hash-limit`, `--max-depth`, `--max-entries` |

`mbr_changed`, `boot_sector_field_changes`, `fat_copies_identical_before/after`,
`fat_sha256_before/after` are part of the diff so a partition-table or BPB
change cannot hide inside "file bytes".

## 7. What the guest can and cannot do today

Can:

- read the MBR partition and FAT16 volume, including both FAT copies;
- list root and nested directories, filter hidden entries and unsupported
  extensions;
- read files: the factory Library titles come from EPUB metadata, and
  CrossPoint rendered the opened EPUB and cached parsed HTML/sections;
- write files: create directories, allocate clusters, write an index
  (factory) and a full EPUB cache/progress/state (CrossPoint);
- keep the source books byte-identical while writing caches beside them.

Cannot (observed or untested):

- no write reaches the host image: the bridge runs a temp copy; write-back to
  the QA media is not implemented and was not tested;
- CrossPoint Browse Files did not show `/.crosspoint` (hidden filter), and in
  this run we did not open `notes.txt` or enter `More Books`, so those two
  paths are listed but not read-proven;
- the factory library lists `notes.txt` but only metadata titles for EPUBs
  were displayed; whether it reads TXT content was not tested;
- FAT32/exFAT, cards with long-name collisions, full-card and wear behaviour
  are out of scope;
- no network, Wi-Fi, timing or multi-device behaviour is implied by this run.

## 8. Limits

- Screenshots are real `/screen.png` frames of the guest SSD1677 RAM; no
  pixels or text were fabricated. Navigation was manual taps at coordinates
  chosen from the captured frames.
- The probe does not parse the binary formats of `library.idx`, `BOOK.BIN`,
  `SECTIONS/0.BIN` or `PROGRESS.BIN`; it verifies them as bytes. The `CLX1`
  magic and the on-screen listing are the only bridges to semantics.
- The factory Library index is written with guest timestamps
  `2026-01-01 00:00:00` on both runs; the emulator's guest RTC is not host time.
- The paired card itself differs from pristine in 33 sectors / 6 clusters
  because macOS created and deleted AppleDouble/FSEvents entries while the
  library was written. Guest diffs in §5.3 and §6 use the paired image as the
  baseline, not pristine.
- UART0 showed only the ROM banner for the factory image; no application
  logging was available to correlate writes.
- One virtual device per bridge; no concurrency or SMP conclusions.

## 10. Reproduce the guest side

```sh

  --pristine <pristine.img> --report /tmp/pristine.json

  --pristine <paired.img> --guest-card <guest-sd.img> --report /tmp/diff.json
```
