# 0085 — sleep/wake: measured evidence, and the lane artefact that was removed

Date: 2026-10-31 (lane) → 2026-11-01 (orchestrator live run).
Lane: batch-5 `sleep-wake`, with `sleep-acceptance` (see
[0091](0091-sleep-acceptance-20261031.md)).

## Verdict

The SSD1677 deep-sleep behaviour **is** proven on the shipped kernel — but not
by this lane's artefacts. The lane's probe had never been executed and could
not have run; the acceptance suite checked a hand-written dictionary. Both
were removed, and the same behaviour was then measured live with the existing
waveform probe.

| Claim | Status now |
|---|---|
| `0x10` + mode byte sets `deep-sleep=1` and `sleep-entries=1` | ✅ measured |
| Every byte after sleep is rejected: `frames` unchanged, no new BUSY edge, `sleep-ignored-bytes` grows | ✅ measured |
| `SW_RESET` (`0x12`) does **not** wake the panel | ✅ measured |
| Only a hardware RESET pulse clears `deep-sleep`, and painting works again | ✅ measured |
| Panel-side timing on a physical SSD1677 | ❌ not measured (host model only) |

## What the lane delivered and why it was removed

`probe_x4pro_sleep_wake.py` (added in `246b628`, then deleted) failed at the
first opportunity to run:

- `:56` and `:68` referenced `socket`, a name never defined in the module
  (the QMP path variable is `sock`) — `NameError` before QEMU is spawned;
- `:68` unpacked `qmp_connect()` as a 3-tuple, but it returns one callable;
- `:73` read properties at `/machine/soc/sqi` with the `ybx-epd-*` prefix.
  The prefixed aliases live on `/machine/soc` (`hw/xtensa/esp32s3.c:868-872`);
  the device object itself uses the unprefixed names
  (`hw/display/ybx_ssd1677.c:338-343`), so every read would have failed;
- `:166` reported `"paint_rejected_by_model": not panels_unchanged or True` —
  a constant `true` regardless of what the guest did;
- it built `EpdPanel(CONFIGS["x4pro"])`, which is the host-side panel
  simulator from `epd_protocol.py`, not a driver: no byte would ever reach
  the emulated device.

`test_probe_x4pro_sleep_wake.py` and `test_x4pro_sleep_acceptance.py` did not
drive any of this either — they asserted against a literal dictionary built
inside the test, so they passed while the probe was broken. A test that cannot
fail when its subject is missing is not acceptance.

The real primitives already existed in
[`probe_x4pro_epd_waveform_qtest.py`](../probe_x4pro_epd_waveform_qtest.py)
(`QTest`, `qmp_connect`, `Epd`, `deep_sleep_sequence()`, `paint_sequence()`),
which is what the run above uses. Anything future sleep work needs is there.
